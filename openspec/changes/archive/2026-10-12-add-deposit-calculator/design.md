# Проектное решение

## Context

Репозиторий пустой (только OpenSpec и README). Мотивация описана в proposal.md, поведение — в `specs/`.
Здесь зафиксированы технические решения, не видимые пользователю. Версии и интерфейсы библиотек
перед использованием сверяются с актуальной документацией (context7), а не берутся по памяти.

## Goals / Non-Goals

**Goals:**
- Ядро расчёта — чистые функции на TypeScript без обращений к странице, полностью покрытые
  тестами по сценариям спецификации.
- Интерфейс тонко оборачивает ядро: компоненты не содержат формул.
- Воспроизводимость: одинаковые входные данные дают одинаковый график до копейки.

**Non-Goals:**
- Сервер и база данных: приложение полностью работает в браузере.
- Многоязычность и серверный рендеринг.

## Decisions

1. **Vue 3 (Composition API, `<script setup>`) + TypeScript + Vite.** Выбор пользователя — Vue.
   Строгая типизация делает контракт ядра явным.
2. **Деньги — `decimal.js`, округление `ROUND_HALF_UP` до копейки в каждом периоде.** Двоичные
   числа дают погрешности (0,1 + 0,2 ≠ 0,3). Округление в каждом периоде делает график
   самосогласованным: сумма строк равна итогу. Цена — расхождение с замкнутой формулой на копейки;
   оно зафиксировано сценарием. Альтернатива — целые копейки: проще, но дробная ставка
   и пропорции периодов требуют промежуточных делений.
3. **Месяц = 1/12 года, а не фактическое число дней.** Проще проверять и объяснять; расчёт
   по фактическим дням вынесен за рамки.
4. **Состояние формы — один компонуемый модуль (`useDeposit`)**, без Pinia и маршрутизатора:
   приложение одностраничное, общего состояния мало. Адрес страницы обновляется через
   `history.replaceState`, чтение — при загрузке.
5. **Оформление — собственный CSS с переменными (дизайн-токены)** в одном файле, без тяжёлого
   набора компонентов. Темы — наборы переменных на корневом элементе; выбор в `localStorage`,
   по умолчанию `prefers-color-scheme`. Вёрстка исключительно по методологии БЭМ. Не использовать Tailwind и Vuetify: быстрее, но размывают единый набор токенов и утяжеляют сборку.
6. **График — Chart.js через `vue-chartjs`.** Лёгкий, поддерживает подсказки и тёмную тему через токены.
   Рядом всегда есть таблица и текстовая сводка как доступная замена.
7. **Тесты:** Vitest для ядра и компонентов (Vue Test Utils); Playwright для сквозных проверок
   (адаптивность, темы, клавиатура, выгрузка CSV) и `@axe-core/playwright` для доступности.
   Тесты пишутся до реализации (TDD), каждый тест называется по сценарию спецификации.
8. **Форматирование чисел и дат — `Intl` с локалью `ru-RU`**, без сторонних библиотек.
9. **Сборка и публикация:** GitHub Actions — проверка типов, тесты, сборка, публикация на GitHub Pages
   (базовый путь задаётся в настройках Vite).
10. **Идентификаторы в коде и названия папок спецификаций — на английском** (технический минимум:
    ключевые слова OpenSpec, имена пакетов, ключи); всё, что видит человек, — на русском.

## Risks / Trade-offs

- [Месяц = 1/12 года отличается от банковского расчёта по дням] → допущение указано в интерфейсе
  и README; значения могут отличаться от калькуляторов банков на несколько рублей.
- [Округление в каждом периоде отличается от замкнутой формулы] → поведение зафиксировано
  сценарием, тест проверяет именно расчёт по периодам.
- [Красота трудно проверить автоматически] → скриншоты Playwright в светлой и тёмной темах на трёх
  ширинах прикладываются к запросу на слияние и просматриваются человеком; доступность проверяется axe.
- [Chart.js добавляет вес] → график подключается отдельным фрагментом, загружаемым лениво.

## Структура проекта

```
src/
  core/         чистое ядро расчёта: типы, проверка, периоды, проценты, даты, график, итоги
  format/       деньги и даты в формате ru-RU, разбор ввода сумм, CSV
  composables/  useDeposit (состояние формы и расчёт), useTheme, useUrlState
  components/   по одному блоку БЭМ на компонент: AppHeader, ThemeToggle, DepositForm,
                SummaryCards, GrowthChart, ScheduleTable, ResultNotice
  styles/       tokens.css (токены и темы), base.css (сброс и типографика)
tests/
  unit/         Vitest: ядро, форматирование, композабли, компоненты
  e2e/          Playwright: адаптивность, клавиатура, доступность, выгрузка CSV
```

## Правила БЭМ

- Один компонент — один блок; имя класса `блок__элемент--модификатор`, только один уровень элементов.
- Классы не зависят от расположения (никаких вложенных селекторов вида `.a .b`), стили блока лежат
  в файле его компонента.
- Состояния темы и ошибок выражаются модификаторами (`.form__field--invalid`), а не отдельными селекторами.
- Цвета, отступы, радиусы, тени берутся только из переменных `tokens.css`.
